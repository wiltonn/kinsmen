# Editing the website: a guide for volunteers

You don't need any technical knowledge. Everything visitors read is edited in **Sanity Studio**, a website for
editing content (ask the webmaster for the address and an invitation).

**When you click Publish, the live website updates by itself within about 3 minutes.**
Drafts (unpublished changes) never appear on the website.

## The golden rules

1. **Only publish facts you've checked.** Dates, prices, hours and contact details must be confirmed by the club.
2. **Enter facts once.** Dates, hours and prices live on the **Season**. Every page reads them from there, so
   never type dates into a description.
3. **Mark it confirmed.** Each item has a _Review status_. Switch it to **Confirmed** once you've checked it.
   Unconfirmed items are flagged on preview builds so nothing slips through.
4. **Describe photos.** Every photo needs _Alternative text_: a short description for people who can't see it.

## Common jobs

### Start a new season (usually in the fall)

1. **Visit the Sugar Bush → Seasons → +** (or duplicate last year's season using the ⋯ menu).
2. Set the **Season year** and **Season status = Upcoming**.
3. **Dates and prices** tab: add each public date. For consecutive days, add one entry with a first and last day,
   e.g. 13 Feb → 15 Feb with the label “Family Day weekend”. Add hours and admission prices when they're confirmed.
   Leave them empty until then; the site says “To be confirmed”.
4. **Pancake House** tab: choose _Same as the public dates_ if that's true, add serving hours, and pick the menu.
5. **School tours** tab: dates, pricing, how to book, teacher downloads.
6. **Reservations** tab: leave as _Not announced_ for now. Answer **“Does a table reservation include a tour?”**.
7. Publish, then go to **Site settings → Current season** and choose the new season. Publish.

### Open Pancake House reservations

1. Check that **Booking settings (OpenTable)** has the booking link (only the OpenTable administrator can supply it).
2. Open the current **Season → Reservations**:
   - Before booking opens: choose **Opening soon**. Add the opening date only if it's confirmed.
   - On the day OpenTable starts taking bookings: choose **Open** and publish.
3. **Reserve a table** buttons appear across the site within a few minutes.

Don't write “sold out”. OpenTable shows which times are available.

### Post a weather alert or closure

**Season → Visitor alert**: type a short message (e.g. “Closed today, Sunday March 7, because of freezing rain”),
choose _Important_, and optionally set **Remove automatically after**. Publish. To remove it early, clear the
message and publish.

### Change a menu price

**Visit the Sugar Bush → Pancake House menus →** this season's menu → edit the price → Publish.

### Update syrup prices

**Maple products → Products** → the product → **Sizes and prices** → Publish.

### Add or change a question (FAQ)

**Visit the Sugar Bush → Visitor questions**. Choose a topic so it appears on the right page. Add it to the
season's _Season-specific questions_ if it only applies this year.

### Replace the teacher's guide PDF

**Visit the Sugar Bush → Downloads (PDFs)** → open it → upload the new file → update the _Edition year_ → Publish.

### Add a community story

**Community impact → Stories → +**. Add a headline, a few short paragraphs and a photo with alternative text.

### Change contact details or where forms go

**Site settings → Contact** and **Site settings → Enquiry routes**. Each enquiry type (school tours,
volunteering, membership, general) has its own destination. A route with an empty destination is hidden. Only
point a route at a form or inbox someone actually checks.

## Writing tips

- Short sentences. Put the most important thing first.
- Write dates as “Saturday, February 13” and times as “9 a.m.”. The site formats dates and prices for you.
- Use link text that says where it goes (“Download the teacher's guide”), not “click here”.

## If something looks wrong

- **Change not showing?** Wait 3–5 minutes and refresh. Check that you clicked **Publish**, not just saved.
- **Red error in the Studio?** Read the message under the field. It explains what's needed (for example, the
  OpenTable link must be an opentable.ca address).
- Still stuck? Contact the webmaster. Every published change is kept in the document's history (⋯ → _History_)
  and can be restored.
